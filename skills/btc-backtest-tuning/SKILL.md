# 回测调参

工具：`btc_backtest`（内置融合策略，全量回测）。`overrides` 只影响**本次**回测，
不会改策略源码 —— 这是刻意设计：先证明有效，再固化。

## 流程（顺序不能反）

1. **拿基线**：`btc_backtest` 不带 overrides，记下 `return_pct` / `max_drawdown_pct` /
   `win_rate` / `pl_ratio` / `sharpe` / `trade_count` / `signal_rate`。
2. **一次只改 1–2 个参数**：`btc_backtest {overrides: {"leverage": 5}}`。
   一次改一堆会说不清是哪一项起作用。
3. **至少比 2–3 组**，确认改进不是单个窗口的偶然。
4. **数据窗口与成本必须一致**：默认全量窗口；要在子区间跑就固定同一个 `start_date`，
   两组之间不能一个全量一个子区间。
5. **有效后才改源码**：改 `assets/btc/core/strategy_core.py` 的 `FUSION_PARAMS`
   （模式目录下的 `core/strategy_core.py`），改完**必须再跑一次全量回测**验证。
6. 同步更新受影响的参数说明（策略文档 / `AGENTS.md`）。

## 常用实验方向（历史结论，仍需自己验证）

| 方向 | overrides | 备注 |
|---|---|---|
| 杠杆 | `{"leverage": 5}` | 降杠杆是改善回撤最有效的手段（9x→5x 时回撤 63%→41%） |
| 止损 / 止盈 | `{"sl_atr": 2.0}` / `{"tp_atr": 4.0}` | 与 `max_hold` 联动，单改易失真 |
| 移动止损 | `{"trail_atr": 2.5}` | 会同时影响胜率与平均持仓 |
| 波动自适应 | `{"use_vol_adaptive": true}` | 历史结论：当前参数下是负贡献，慎用 |

## 口径（对比前先确认一致）

- 成交假设：信号日**收盘价**成交，只扣手续费（0.05%）与资金费（0.01%/8h），**无滑点**
  → 收益天然偏乐观，对外报数必须带这个前提；
- 回测窗口从配置的起点算起，含预热；不同起点的收益不可直接比较；
- 指标键固定在返回值里（`metrics`），不要自己换算单位。

## 结论格式

```
基线：收益 X% / 回撤 Y% / 胜率 W% / 盈亏比 P / 夏普 S / 交易 N 笔
新参：收益 X'% / 回撤 Y'% / ...
结论：<一句话建议，说明是改善哪个维度、牺牲了什么>
```

不给"看起来更好"这种判断 —— 必须指出改善的指标与代价（回撤换收益 / 交易次数换胜率）。
