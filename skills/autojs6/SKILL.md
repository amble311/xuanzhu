# 通过 AutoJs6 操作手机

手机上的 **AutoJs6** 提供无障碍能力；xzh 通过设备桥把脚本推过去执行、再把日志收回来。
所以"操作手机"= **写一段 AutoJs6 脚本 → 推过去执行 → 读日志确认**。

| 工具 | 作用 |
| --- | --- |
| `device_run` | 把脚本文件推到手机并**立即运行**（最常用） |
| `device_logs` | 读取手机上的输出（脚本 `console.log` 的内容） |
| `device_read_screen` | **读手机当前界面内容（文字）** —— 你"看"屏幕的正确方式 |
| `device_screenshot` | 截图存文件（**只给用户看**，模型看不到图） |
| `device_list` / `device_stop` | 看手机是否已连接 / 停掉卡住的脚本 |

---

## 一、三条硬约束（先看，否则一定踩）

1. **脚本在手机上跑，xzh 拿不到返回值** —— 必须主动回报。
   `device_run` 只负责"送过去并启动"，返回值与异常栈**都不会自己回来**，
   **每段脚本都要把关键结果打进日志**：
   - **一律 `console.log`**：与 `toastLog` 走同一条日志通道（你都读得到），
     但**不会在用户屏幕上弹气泡**（每步弹一下很烦，还会混进界面里干扰读数）；
   - `toastLog()` / `toast()` **只在必须让用户当场看到**时用（如"请手动点一下授权框"）；
   - 关键结果加**可搜索前缀**：`【步骤1】` / `【结果】` / `【失败】`；
   - **一定要包 try/catch 并把异常打出来**，否则只剩一行栈看不出意图。
2. **推送是"发出即返回"，日志**异步**回流**：
   `device_run(脚本) → sleep 1~3 秒（按脚本时长调整）→ device_logs → 判断`。
   含 `sleep()` / 打开应用 / 等界面的脚本要相应延长等待。
3. **手机只有一台，且脚本会挂住**：
   - 上一条没跑完就推下一条，两者会**同时在手机上跑、互相抢界面** → 动手前先 `device_logs` 看残留；
   - 用了 `waitFor()` / `waitForActivity()` / 死循环的脚本**可能一直挂着** → 收尾用 `device_stop`；
   - 动作类脚本要**短、单目标**，一次只做一件可验证的事 —— 手机上出错很难远程调试。

## 二、无障碍是前提（UI 脚本必写）

```js
auto.waitFor(8000);   // ✅ 可带超时；服务就绪时几乎零成本（实测 3ms 返回），未就绪则等待
if (!auto.isRunning()) { console.log("【失败】无障碍服务未就绪"); exit(); }
```

❌ **不要用 `auto()`** —— 服务没真正运行时**直接抛错**。实测两种状态：

| 现象 | 含义 | 处理 |
| --- | --- | --- |
| 抛 `无障碍服务未启动` | 用户在设置里**没开** | 让用户去「设置 → 无障碍 → 已安装的服务 → AutoJs6」开启 |
| 抛 `无障碍服务已启用但未运行` | 开了但被系统判定没跑起来 | 让用户**关掉再打开**该开关，或重启手机 |

只用 `console.log` / 文件 / 网络这类**不需要无障碍**的脚本可以不写。

## 三、脚本模板（照抄改）

```js
try {
  auto.waitFor(8000);                     // UI 脚本必写
  console.log("【步骤1】启动目标应用");
  app.launchPackage("com.example.app");   // 换成目标包名
  sleep(2000);

  console.log("【步骤2】找到并点击");
  var btn = text("确定").findOne(5000);    // 带超时，找不到返回 null
  if (!btn) {
    console.log("【失败】没找到「确定」，当前界面=" + currentPackage() + "/" + currentActivity());
    exit();
  }
  btn.click();
  sleep(1000);

  console.log("【结果】成功，界面=" + currentActivity());
} catch (e) {
  console.log("【失败】异常：" + e);
}
```

- `findOne(timeout)` **永远判空**，别假设一定找到；
- 失败分支**必须**打出 `currentPackage()` / `currentActivity()` —— 判断"停在哪"的唯一线索；
- `exit()` 提前结束，避免在错误界面上继续乱点。

## 四、安全红线：多开 / 克隆应用的选择弹窗

`app.launchPackage()` 后可能先弹「用哪个应用打开」的选择框（支持应用分身的手机很常见）。
**三条禁止**（真实踩过，代价很大）：

1. **不要点「取消」** —— 那是"放弃这次操作"，不是"关掉弹窗"的通用手段；
2. **不要勾「不再询问 / 使用主应用打开，不再询问」** —— **永久改变用户的系统设置**，不可逆，
   只有用户明确同意才能勾；
3. **不要替用户随机挑一个** —— 选错分身 = **操作了另一个账号**，表面成功、实际全错，极难发现。

正确做法：`console.log` 把候选**报给用户** → 等他明确说用哪个 → 用 `storages` 记住 → 之后复用。
判据与完整代码见 `references/patterns.md`。

## 六、写脚本前先想清楚这三句

1. **怎么知道成功了？** —— 没有可读的日志输出，就等于没做（约束 1）。
2. **怎么知道失败了、停在哪？** —— 失败分支必须打出 `currentPackage()` / `currentActivity()`。
3. **会不会挂住？** —— 阻塞调用要带超时；会挂住的脚本记得 `device_stop`。
