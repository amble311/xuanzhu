# 排查清单

> `autojs6` 技能的伴随文件。**先确认"脚本有没有把话说出来"** —— 一半问题都是没输出。

| 现象 | 原因 / 处理 |
| --- | --- |
| `device_run` 报"没有设备" | 手机没连：让用户开 AutoJs6 的「连接电脑 → 客户端模式」（填 xzh 打印的地址），或检查 xzh 侧是否在监听 |
| 脚本推了但日志里什么都没有 | 脚本没输出（回到主文件约束 1）；或还没跑完（多等几秒，或用 `device_logs` 多读几次） |
| 日志里混进了**上一次**运行的残留 | 日志缓冲是**跨调用共享**的：本次运行要打唯一标记（如 `【开始】<runId>`），只取标记之后的行 |
| 报 `无障碍服务未启动` / `已启用但未运行` | 见主文件第二节；让用户开启，或**关掉再打开**该开关 |
| 点不到 / 点错位置 | 控件没加载完（`sleep` 不够）；或该加 `setScreenMetrics` 后走坐标兜底 |
| `findOne` 返回 `null` | 界面不对：先把 `currentPackage()` / `currentActivity()` 打出来确认停在哪；或该界面**根本不给无障碍节点**（见下） |
| 控件读不到（节点数 0 / 极少） | 自绘界面、跨用户空间的应用分身、或对无障碍做了限制的 App ⇒ **立刻**改走截图 + 坐标，别反复试选择器 |
| 脚本似乎一直不结束 | 用了 `waitFor()` / `waitForActivity` / 死循环，或调了 `KeyCode()` / `Input()` 这类**特权命令**在等授权 ⇒ `device_stop` 收尾 |
| `$shell` 报 `Permission Denial` / `code=255` | 该命令需要更高身份（`dumpsys` 要 DUMP、`input` 要 INJECT_EVENTS）⇒ 见 `input.md` 的授权步骤 |
| 截图卡住 / 拿不到图 | MediaProjection 授权框没被点掉 ⇒ 见 `screenshot.md` 的线程样板 |
| 截完图**输入框失焦、键盘收起** | 授权框抢焦点所致 —— 正常现象，见 `screenshot.md` |
| 手机会周期性掉线（十几秒后自己回来） | 系统后台限制（OPPO / 小米 / vivo 常见）：让用户把 AutoJs6 的**电池优化关掉**、允许后台运行 |
| 需要更细的 API | 官方文档 <https://docs.autojs6.com>；AutoJs6 是开源的，各 API 的实现在其源码 `app/src/main/java/.../runtime/api/augment/` 目录下（按 augment 文件名对应全局函数） |

## 回报格式建议

排查快慢几乎只取决于日志。建议每条关键输出都带前缀，日志一眼能扫：

| 前缀 | 含义 |
| --- | --- |
| `【步骤N】` | 正在做什么 |
| `【结果】` | 成功，附当前界面 |
| `【失败】` | 失败，**必须**附 `currentPackage()` / `currentActivity()` 与原因 |
| `【判断】` | 你的结论（如"控件数 0 ⇒ 自绘界面"） |
| `【完成】` | 脚本收尾标记 |
