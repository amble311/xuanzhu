# 叫醒条件（阈值监控）

`btc_trigger` 把条件落盘到 `~/.btc/run/triggers.json`，常驻后端**每 5 分钟评估一次**
（价格用实时标记价，指标读本地库），命中才跑一轮巡检 —— 不命中不调模型，所以很便宜。

**它只叫醒，不下单。** 下单仍由那一轮巡检按三周期打分 + 风控判断。

## 什么时候用

| 用户说 | 用什么 |
| --- | --- |
| 「到 80000 提醒我」「跌破 75000 叫我」 | `btc_trigger`（price） |
| 「RSI 跌破 30 就看一眼」「ADX 上 40 提醒我」 | `btc_trigger`（indicator） |
| 「30 分钟后看看」 | `btc_schedule`（排期，不是条件） |
| 「以后别逆势、单笔最多 1%」 | `btc_policy`（长期指令） |

条件与排期的区别：排期是**到点就看**，条件是**到了才看**。
两者可以并存 —— 常规节奏交给 `btc_schedule`，关键位置交给 `btc_trigger`。

## 参数

| 参数 | 说明 |
| --- | --- |
| `action` | `add` / `list` / `remove` / `clear` |
| `kind` | `price`（价格）/ `indicator`（单个指标）/ `formula`（受限公式） |
| `expression` | `kind=formula` 必填：如 `rsi_1h * 0.6 + adx_1h * 0.4` |
| `op` | `>=` / `<=` / `>` / `<` |
| `value` | 阈值。价格单位 USDT；RSI/ADX 是 0–100；`ma_gap_pct` 是相对 MA20 的百分比 |
| `name` | `rsi` / `adx` / `ma_gap_pct` / `macd_hist`（kind=indicator 必填） |
| `timeframe` | `1h` / `4h` / `1d`，默认 `1h` |
| `once` | 默认 `true`：命中一次就失效；`false` 为持续监控 |
| `cooldown_min` | 持续型的最短触发间隔，默认 30 分钟 |
| `expires_hours` | 多久后自动失效，默认 72，最长 168 |
| `window_start_hour` / `window_end_hour` | 只在此时段（**北京时间**整点）评估；两个一起给才生效，止 > 起跨午夜 |
| `side_hint` | `long` / `short`：命中时的方向倾向（给巡检的上下文，不是指令） |
| `note` | 用户原话，命中时注入巡检提示词 |

## 用法要点

1. **一条一个条件**，便于之后单独删；`remove` 用 `list` 里的 id。
2. 上限 10 条 —— 超过说明该把关注点收敛成一条策略（`btc_policy`）。
3. 默认一次性：多数「到某价提醒我」是一次性关注点，命中后不该再叫。
4. 设置后告诉用户**具体条件**（工具返回里有全文），不要只说「已设置」。
5. 指标数据来自本地库：`btc_status` 显示数据落后时先 `btc_sync`，否则条件可能基于旧 K 线。
6. **时段窗口**用北京整点：`window_start_hour=21, window_end_hour=0` 表示 21:00–23:59
   （止 = 0 指 24:00）。历史数据上 21–23 点的波动显著高于白天，且集中在工作日
   （美股时段），所以「只在晚上盯」比全天盯更省，也更容易命中。
   窗口外条件保留、只是不评估；不要用窗口去替代有效期。

### 受限公式（`kind=formula`）

用户要的是**组合条件**时用它（单指标用 `indicator` 更清楚）：

```
rsi_1h * 0.6 + adx_1h * 0.4  >= 55        # 指标加权
(close_1h - ma20_1h) / atr_1h >= 2        # 价格偏离 MA20 的 ATR 倍数
abs(close_1h - price) / price >= 0.01     # 现价与 1h 收盘的偏离
```

- 变量：`close / rsi / adx / macd_hist / ma_gap_pct / atr / ma20 / ma50 / vol_ratio`
  × `1h / 4h / 1d`，再加 `price`（实时标记价）；
- 运算：`+ - * / %`、括号、比较、`and/or/not`；函数只有 `abs / min / max`；
- **不是任意代码**：导入、属性访问、下标、lambda、赋值全部拒绝，求值在计算层按 AST 白名单执行；
- 表达式要算出**数值**，阈值仍由 `op`/`value` 给。若表达式里写了比较（`... > 55`），
  结果是 1/0，阈值请写 `0.5` 或 `1`；
- 变量拼错/除零会写回 `lastError`（`list` 里显示 `⚠ 求值失败`）——
  看到它要改表达式，别当成「条件还没到」。

## 反例

- 把「这次先别买」写成叫醒条件（那是当前决策，不是条件）；
- 用叫醒条件代替排期（没有任何阈值时它永远不会命中）；
- 设「RSI > 500」这类永远不成立的条件；
- 用公式做本该由代码决定的事（改策略、改风控阈值、下单）—— 公式只能触发出「叫醒」；
- 写 `import os`、`obj.attr`、`x[0]` 这类表达式：会被直接拒绝，不要反复尝试绕过。
- 命中后不看三周期打分直接下单 —— 叫醒只是提醒「值得看了」，不是交易信号。
