# 模拟盘交易

模拟盘用**同一份行情库**、**同一个策略判断**，但成交记在本地虚拟账本上（`paper_account` /
`paper_trades` 两张表），**不涉及真钱**。它存在的意义：让后台巡检在真实推进的行情上
验证决策，产出可复盘的绩效，而不是纸上谈兵。

## 三个工具

| 工具 | 作用 |
| --- | --- |
| `btc_paper_status` | 权益、现金、持仓、浮动盈亏、胜率、最近成交 |
| `btc_paper_open` | 挂限价单：`side`、`limit_price`、`notional`、`stop_price`、`reason` |
| `btc_paper_cancel` | 撤未成交挂单（不传 id 撤全部） |
| `btc_paper_close` | 平仓：`reason` |
| `btc_paper_reset` | 清空账本（**仅用户明确要求时**；会弹确认，后台巡检里必被拒） |

## 先算保证金与倍率（合约，不是现货）

模拟盘是**合约**：现金只被占用为保证金，所以下单前必须同时看三个数：

| 数 | 从哪来 | 怎么用 |
|---|---|---|
| 可用余额 | `btc_paper_status` 的 `available` | 决定这单能不能挂 |
| 占用保证金 | `margin_used`（持仓 + 未成交挂单） | 判断还剩多少空间 |
| 倍率 | `leverage` 参数；不传则读实盘杠杆，再取不到用 `BTC_PAPER_LEVERAGE` 或 9x | 名义 ÷ 倍率 = 这单要占多少保证金 |

- 需要占用的保证金 ≈ `名义 ÷ 倍率`，再加手续费（0.05%）；
- **倍率不是越高越好**：同样名义占用更少，但强平价更近。开仓前说清「倍率 + 占用 + 可用」，别只报名义；
- **余额不足时会自动提倍率**（上限 20x）：不传 `leverage` 时，代码把它提到「刚好够开这一单」，
  返回里标「倍率已自动提高」；超过 20x 仍不够就拒绝，并给出「20x 下最多可开多少名义」。
  提到 17x 不是什么好事 —— 强平价会同步拉近，报给用户时要讲清楚；
- **显式给了倍率就不会被自动改**：比如你给 5x，余额不够时工具直接拒绝并告诉你「至少需要 17x」，
  要不要提是你的判断，不要为了避免拒绝就无脑给 20x；
- 加仓时占用按「总名义 ÷ 等效倍率」累加，多档挂单也会合计校验。

## 成交与成本口径（报数时必须一致）

- **限价挂单**：价格到达限价即成交。**限价已在市场另一侧时会挂出即成交**（真实交易所的吃单），
  成交价取「限价与市价中更优者」（多头 min、空头 max），不会比限价更差；
  工具返回会明确区分「已成交」与「已挂单」，别把立即成交说成挂着等；
- **价格源**：优先实时标记价（`mark_price`），取不到才用库内最新收盘价 —— 后者会标注
  「可能滞后」，此时结论要带上「按旧收盘价估算」；
- 未成交的挂单会一直留着，直到**时效到点**（`expires_min`，默认 60 分钟）或主动撤单；
  超时仍未成交时后端会叫醒一轮巡检 —— 那一轮要给出「撤单 / 改价 / 继续等」的明确处理；
- 手续费 **0.05%**，开平各收一次；**不计资金费**（模拟盘只验证方向与仓位）；
- 同时只允许**一个持仓**，已有持仓必须先 `btc_paper_close` 再开新仓；
- 初始资金默认 100000 USDT（可用 `BTC_PAPER_CAPITAL` 改，重置时也可指定）。

## 开仓前必须交代

方向、名义金额、止损价、依据（哪几个指标 / 哪个周期）。缺一项就不要调用工具。
平仓后必须回报：成交价、盈亏金额、以及平仓后的权益与收益率变化。

## 边界（说错会误导用户）

- **绝不能说成「实盘已成交」**：它是模拟撮合，没有真实委托、没有交易所成交回报；
- 不要把模拟收益当成实盘业绩，也不要用它推断「实盘一定能做到」——
  模拟盘没有真实滑点、没有资金费、没有部分成交（只有资金不足时按可用现金缩量）；
- 模拟盘亏损同样要如实报，不要只报盈利笔；
- 重置账本会抹掉全部绩效记录，只在用户明确要求时执行；
- 重置会**留痕**：`/reset moni` 与 `btc_paper_reset` 都会把「重置前几笔成交、盈亏、
  原持仓/挂单、资金变化」写进项目记忆。所以重置后**先读记忆再回答**，
  不要说「之前没发生过交易」。

## 面板与重置

- `xzh btc moni` 的右侧面板显示**虚拟账本**（权益 / 现金 / 持仓 / 挂单 / 已平仓绩效），
  不显示真实账户 —— 引用面板数字时别忘了它是模拟的；
- 用户说「重置模拟盘」「初始资金改成 20 万」→ 让他输入 `/reset moni 200000`
  （重置账本会清空持仓、挂单与全部成交记录，**必须由用户主动执行**）；
- 工具 `btc_paper_reset` 同样能重置，但它需要确认，后台巡检里会被拒；
- 两种方式都会写记忆（包括重置前的绩效）。重置后要如实转述「清掉了什么」，
  不要把清零后的账本说成「一直没交易过」。

## 与巡检的关系

`xzh btc moni` 的常驻后端在巡检时会自己决定是否虚拟开平仓（提示词里允许）。
它的结论写进 `<模式目录>/logs/inspect.log`，账本状态可以用 `btc_paper_status` 或
`xzh btc status` 查看。前台对话与后台巡检**不共享上下文**，需要对齐时先看账本状态。
