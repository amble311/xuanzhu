币安（Binance）口径

本文件只写**平台口径**，不写调用方法 —— 拉数据、分页、代理都已在代码里
（`src/exchange/binance.ts`），模型不需要也不应该用 `bash` 手拼 HTTP。

## 端点与市场类型

| 市场 | 基础地址 | K 线路径 |
|---|---|---|
| 合约（默认） | `https://fapi.binance.com` | `/fapi/v1/klines` |
| 现货 | `https://api.binance.com` | `/api/v3/klines` |

切换方式：环境变量 `BTC_USE_FUTURES=0` 走现货，其它值（含未设置）走合约。
默认合约是因为策略的回测成本里含**资金费**，现货没有这一项，口径会对不上。

## 符号

- 通用写法 `BTC/USDT`，适配器转成 `BTCUSDT`（去掉非字母数字并大写）；
- 库里的 `symbol` 字段**始终存通用写法**，这样换平台后同一个币不会变成两条数据；
- `BTC_SYMBOL` 可改标的（默认 `BTC/USDT`），Python 与 Node 读同一个变量。

## 时间与周期

- K 线开盘时间是 **UTC 毫秒**；日线按 UTC 00:00 对齐（北京时间 08:00）；
- 入库存 UTC 毫秒，读库后统一转 `Asia/Shanghai` —— 换算只在 Python 一处，
  不要在外层再做一次（历史上因此整体偏 8 小时，导致日期错位）；
- 周线是本地用日线重采样（`W-FRI`，标签取周起始日），不需要单独同步。

## 分页与限频

- 单次最多 1000 根；代码用 `startTime` 游标往后推，天然去重；
- 超限返回 HTTP 429 / 418：**不要重试刷接口**，等一会儿再同步；工具会把状态码原样报出来；
- 公开行情不需要 API Key；私有接口（账户/下单）目前未接入。

## 成本口径（回测与报数必须一致）

| 项 | 取值 | 说明 |
|---|---|---|
| 手续费 | 0.05%（`fee_pct=0.0005`） | 单边，开平各一次 |
| 资金费 | 0.01% / 8h | 日线每根按 3 期计 |
| 滑点 | 0 | 按信号日收盘价成交，因此结果偏乐观 |

报收益时必须带上这三项，尤其是「无滑点」这一条。

## 已知坑

- 当日 K 线在收盘前是**进行中的快照**，同步到它属于正常现象，不要当成数据错误；
- 不同平台的合约乘数、最小下单精度（`stepSize` / `tickSize`）不同，接入下单前必须先读
  平台的 exchangeInfo，不能沿用币安的精度；
- 币安会给 `418`（被限流封 IP）而不是 `429`，两者处置相同但恢复时间更长。
